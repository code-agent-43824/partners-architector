# D9 — Импорт результатов теста совместимости (ПЕСП)

**Status:** IN PROGRESS (plan committed before code, per AGENTS.md).
**Owner request (2026-08-18):** Гриц и Кибкало выпустили «Тест естественной
совместимости партнёров» (ПЕСП) — Telegram Mini App (анонс:
t.me/DeanIBL/1212, 2026-08-13): 184 вопроса, 32 конструкта в трёх блоках
(Различие / Паритет / Совпадение), парная «матрица естественной
совместимости» с зонами-светофором и интегральный балл ПЕСП (уровни A–D),
PDF-отчёт. Формат их экспорта нам пока неизвестен (вероятно, позже будет
JSON). Владелец решил: **уже сейчас** в интерфейсе должны быть кнопки
импорта результатов тестирования, импорт должен принимать любой файл, и
интерфейс должен явно показывать, что вопросы сессии адаптированы по
результатам тестирования партнёров. Историю «личный кабинет партнёра +
выбор/добавление своих вопросов» (Phase 6, `questionnaire_invite`/`answer`)
это НЕ заменяет — она остаётся в роадмапе.

## Scope (D9 = T1 из трёхэтапного плана интеграции)

1. **API — модуль `test-import` + миграция №3 (`test_import`).**
   - Таблица `test_import`: id, partnership_id (FK cascade), file_name,
     mime_type, size_bytes, data (bytea — сырой файл сохраняем, чтобы
     распознать позже, когда формат ПЕСП станет известен), status
     (`received` | `parsed`), payload (jsonb, nullable), uploaded_at.
   - `GET/POST /partnerships/:pid/test-imports` (POST — multipart, любой
     файл до 10 МБ; multer идёт в комплекте `@nestjs/platform-express`,
     новых зависимостей нет), `PATCH …/:importId/zones` (ручная разметка
     зон), `DELETE …/:importId`. Всё под auth+CSRF+SEC-5 (владение кейсом).
     Ответы никогда не включают сырые байты файла.
   - Парсер: если файл — JSON нашего **предварительного формата
     `psa-pesp-v0`** (см. ниже) — статус `parsed`, payload с зонами/баллом;
     любой другой файл — статус `received` («принят, формат будет распознан
     позже»), зоны можно отметить вручную.
2. **Web — шаг «Совместимость» в карточке кейса.** Степпер D8 расширяется
   до четырёх шагов: Партнёрство → Участники → **Совместимость** → Сессии
   (шаг необязательный — CTA «Далее: сессии» не блокируется). На шаге:
   кнопка «Импортировать результаты (файл)», список загрузок со статусами
   и удалением, сводка распознанного отчёта (балл/уровень/зоны), ручной
   редактор зон по справочнику конструктов, приватная пометка (данные
   остаются на этом сервере — SEC-4/самохостинг).
3. **Адаптация сценария.** Красные/жёлтые зоны активного (последнего)
   импорта маппятся на блоки 1–30 (черновой справочник соответствий
   `конструкт → вопросы` в web-константе). В сценарии: баннер «Сценарий
   адаптирован по результатам теста совместимости (N зон внимания)»,
   маркеры на пунктах оглавления, плашка внутри блока с именем конструкта,
   зоной и парными значениями.
4. **Guided-онбординг**: новый kind `compatibility` со своим гайдом
   (что это, зачем, что будет дальше — нативное прохождение теста по
   ссылке-приглашению, автопарсинг отчётов ПЕСП); тексты шагов 1–4
   обновляются («из 3» → «из 4»).
5. **Демо**: у демо-кейса кофейни в сиде появляется распознанный
   демо-отчёт (балл 71, уровень B; красные зоны → блоки №9/№29/№20/№21 —
   ровно те, что в демо-кейсе отложены/частично подтверждены; жёлтые →
   №5/№6/№22/№24); в `docs/demo/` кладётся образец файла для живого
   импорта на демо; демо-скрипт получает такт про адаптацию. Кейс Грица
   на проде сид не трогает (см. оперативную заметку Watson от 2026-07-24).
   API-e2e (`tests/e2e/run.mjs`) дополняется секцией test-imports.

## Предварительный формат `psa-pesp-v0`

Наш собственный временный формат до появления официального экспорта ПЕСП
(строгая zod-схема, всё лишнее отвергается; в БД сохраняются только
провалидированные поля):

```json
{
  "format": "psa-pesp-v0",
  "partners": ["Анна", "Дмитрий"],
  "score": 72,
  "level": "B",
  "constructs": [
    {
      "code": "risk_attitude",
      "name": "Отношение к рискам",
      "block": "Паритет",
      "zone": "red",
      "values": [30, 85]
    }
  ]
}
```

`zone` ∈ green|yellow|red; `values` — балл каждого партнёра 0–100 (по
порядку `partners`, поддерживаем 2–5 значений — наши кейсы до 5 человек);
`score` 0–100 и `level` A–D опциональны. Когда официальный формат станет
известен, добавится второй парсер рядом (сырые файлы уже сохранены — их
можно будет распознать задним числом).

## Справочник конструктов и маппинг на блоки (v0, ЧЕРНОВОЙ)

32 конструкта переписаны с **открытых маркетинговых материалов** ПЕСП
(анонс + публичные скриншоты профиля); часть названий восстановлена
неуверенно и помечена в коде. Маппинг `конструкт → вопросы 1–30` — наша
рабочая гипотеза для подсветки; канонические названия и маппинг нужно
сверить с Грицем (вопрос к демо). ВАЖНО (IP): банк из 184 вопросов,
формулы скоринга, пороги зон и тексты вердиктов — собственность
Грица/Кибкало; в репозиторий не попадают ни при каких условиях без
письменной договорённости (протокол как с методичкой O1). D9 не
администрирует тест — только принимает и отображает результаты.
